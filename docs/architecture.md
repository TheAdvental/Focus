# Як усе влаштовано

## Частини

```
                     ┌──────────────────────────────┐
                     │  Сервер (server/server.js)   │
                     │  база · календар · MCP       │
                     └───────┬───────────┬──────────┘
            синхронізація    │           │   /api/state
        ┌────────────────────┤           └──────────────┐
        │                    │                          │
┌───────▼────────┐  ┌────────▼─────────┐  ┌─────────────▼────────────┐
│ Браузер        │  │ Програма для ПК  │  │ Android                  │
│ index.html     │  │ Electron         │  │ WebView + служба         │
└────────────────┘  │ index.html       │  │ index.html               │
                    │ закриває .exe    │  │ накладка, будильники     │
                    └────────┬─────────┘  └──────────────────────────┘
                             │ 127.0.0.1:47600/state
                    ┌────────▼─────────┐
                    │ Розширення       │
                    │ блокує сайти     │
                    └──────────────────┘
```

Головний принцип: **увесь інтерфейс і вся логіка — в одному файлі `index.html`**. Програма для ПК і додаток для Android — це оболонки, які показують той самий файл і додають те, чого сторінка не може: закривати чужі програми, малювати поверх інших вікон, працювати у фоні.

| Шлях | Що це |
|---|---|
| `index.html` | Інтерфейс, логіка, стилі, переклад. Без збірки й зовнішніх залежностей |
| `server/server.js` | Сервер на Node.js без залежностей |
| `desktop/main.js` | Оболонка для ПК: вікно, трей, закривання програм, локальна адреса для розширення |
| `desktop/preload.js` | Міст між сторінкою й оболонкою для ПК |
| `desktop/icon.js` | Малює логотип попіксельно; створює PNG та ICO |
| `desktop/build.js` | Збирає `dist/Focus` |
| `extension/` | Розширення MV3: `background.js` стежить за вкладками, `blocked.html` — сторінка-заглушка |
| `android/…/MainActivity.java` | WebView зі сторінкою і мостом `AndroidBridge` |
| `android/…/BlockService.java` | Служба спеціальних можливостей: стежить за відкритою програмою, малює накладку |
| `android/…/Reminders.java`, `ReminderReceiver.java` | Системні будильники для нагадувань |
| `android/…/Store.java` | Спільні налаштування між сторінкою і службою |

## Модель даних

Стан сторінки — один об'єкт `S`, який зберігається в `localStorage` під ключем `focus-app-v1`.

**Завдання** (`S.tasks`):

| Поле | Значення |
|---|---|
| `id` | Унікальний рядок |
| `title`, `firstStep`, `why` | Тексти |
| `planDate` | `РРРР-ММ-ДД` або порожньо |
| `planTime` | `ГГ:ХХ` або порожньо |
| `deadline` | `РРРР-ММ-ДД` або порожньо |
| `done`, `doneAt` | Чи виконано і коли |
| `del` | `true` — завдання видалене (запис лишається як мітка для інших пристроїв) |
| `created`, `u` | Час створення і час останньої зміни, мс |

**Сесії** (`S.sessions`): `id` (`'s' + час старту таймера`), `kind` (`focus` або `break`), `taskId`, `title`, `start`, `end`, `min`, `u`.

**Причини відкладання** (`S.stuck`): `id`, `at`, `reason`, `taskId`, `u`.

**Звички** (`S.habits`) — шаблони повторюваних завдань:

| Поле | Значення |
|---|---|
| `id`, `title` | Ідентифікатор і назва |
| `mini` | Мінімальна версія (стає першим кроком завдання) |
| `cue` | Сигнал: після чого або де |
| `note` | Нотатка до звички загалом |
| `time` | `ГГ:ХХ` або порожньо |
| `days` | Дні тижня числами, 0 — неділя |
| `del`, `created`, `u` | Як у завдань |

У кожен свій день звичка перетворюється на звичайне завдання з ідентифікатором `h:<звичка>:<дата>` і полями `habitId` та `mini` (чи виконано лише мінімальну версію). Завдяки цьому нагадування, фокус і блокування працюють для звичок без окремого коду.

Особливості:

- Завдання дня створює кожен пристрій сам, при першому показі плану. Воно отримує час зміни «початок доби», а не «зараз»: тоді всі пристрої створюють однаковий запис, і справжня зміна на будь-якому з них перемагає.
- Через це невиконане завдання звички на сервер не надсилається. Сервер для Claude обчислює його зі шаблону сам.
- Нотатка за день лежить у полі `note` завдання цього дня. Якщо завдання ще немає (минулий день, який не відкривали), воно створюється в момент першої відмітки чи нотатки — уже зі справжнім часом зміни.
- Відмітка за минулий день отримує `doneAt` на полудень того дня, а не «зараз».
- Пропущені дні не зберігаються як записи: «пропуск» — це день звички, за який немає виконаного завдання. З цього ж рахується позначка «не пропусти двічі».

**Одиничні значення:** `S.timer` (поточний таймер або `null`), `S.settings` (`focus`, `brk`, `remind`), `S.blocklist` (`sites`, `apps`). Час їх останньої зміни лежить у `S.kvu`.

**Те, що не синхронізується** — окремі ключі `localStorage`:

| Ключ | Що в ньому |
|---|---|
| `focus-app-v1-sync` | Адреса сервера, ключ, стан синхронізації |
| `focus-app-v1-cal` | Остання отримана копія подій календаря |
| `focus-app-v1-rem` | Які нагадування сьогодні вже показано чи відкладено |
| `focus-app-v1-theme`, `-lang`, `-music` | Тема, мова, чи ввімкнена музика |

## Синхронізація

Правило одне: **перемагає запис із пізнішим часом зміни `u`**.

1. Пристрій надсилає серверу все, що змінилось після попередньої синхронізації, і номер останньої відомої йому ревізії.
2. Сервер приймає запис, лише якщо його `u` новіший за збережений, і присвоює йому наступний номер ревізії.
3. Сервер повертає всі записи з ревізією, більшою за ту, що назвав пристрій.
4. Пристрій застосовує отримане за тим самим правилом.

Синхронізація запускається через 1,2 с після будь-якої зміни, кожні 20 с і коли вікно стає видимим.

Особливості:

- **Дві вкладки одного браузера.** Кожна тримає свою копію даних у пам'яті. Щоб старіша не затерла новішу, вкладка слухає подію `storage` і перечитує дані, щойно інша вкладка їх зберегла.
- **Видалення** передається як запис із `del: true`, інакше інший пристрій повернув би завдання назад.
- **Подвійний запис сесії** неможливий: коли таймер завершується на двох пристроях одразу, обидва створюють сесію з однаковим `id`.
- **Втрата бази сервера.** Сервер має випадковий ідентифікатор бази (`epoch`). Якщо пристрій бачить інший, він надсилає й забирає все заново.
- **Годинники пристроїв мають іти однаково** — правило спирається на час.

## Хто кому що повідомляє

**Сторінка → оболонки.** Єдина функція `pushDesktop()` викликається після кожного збереження і передає: чи триває фокус, коли закінчиться, назву завдання, списки блокування, мову.

- На ПК це йде в `main.js` через `window.desktop.setFocus`.
- На Android — у спільні налаштування через `AndroidBridge.setFocus`.

**Програма для ПК → розширення.** `main.js` тримає локальну адресу `http://127.0.0.1:47600/state`. Розширення звертається до неї, коли вкладка змінює адресу, коли ти перемикаєш вкладку, і кожні 30 секунд.

**Телефон ↔ сервер.** Якщо сесію запущено на ПК, сторінка в телефоні може бути «заснулою». Тому служба блокування, побачивши заборонену програму без локальної сесії, сама питає сервер (`/api/state`), не частіше ніж раз на 15 секунд.

## Блокування

**Програми на ПК.** Кожні 4 секунди під час фокусу `main.js` читає список процесів (`tasklist`). Знайдений процес зі списку отримує `taskkill` без примусу; якщо на наступній перевірці він ще живий — із примусом. Системні процеси і сам «Фокус» захищені від потрапляння в список.

**Сайти.** Розширення замінює вкладку сторінкою `blocked.html?u=<адреса>`. Сторінка опитує стан кожні 3 секунди і повертає оригінальну адресу, щойно фокус закінчився або програма для ПК закрилась.

**Програми на Android.** Служба отримує подію, коли на передній план виходить інша програма. Якщо та в списку і триває фокус, служба натискає «Додому» і додає поверх екрана власне вікно-накладку. Це зроблено саме накладкою, а не окремим екраном програми, бо деякі прошивки (Xiaomi/POCO) мовчки забороняють відкривати екрани з фону.

## Нагадування

Реалізацій дві, бо на Android сторінка у фоні не працює.

- **У сторінці** кожні 15 секунд перевіряється, чи є завдання, час якого настав. Показується вікно; на ПК оболонка додатково підіймає вікно з трею.
- **На Android** сторінка після кожного збереження передає список майбутніх завдань у `Reminders.java`, а той ставить точні системні будильники. Після перезавантаження телефона будильники відновлюються зі збереженого списку.

Нагадування не показується, якщо триває фокус, якщо за завданням сьогодні вже була сесія або якщо від запланованого часу минуло понад годину.

## Календар

Сервер завантажує календар за таємною адресою iCal, розбирає події й розгортає повтори (щоденні, щотижневі з днями тижня, щомісячні за числом, щорічні; винятки й скасовані події враховуються). Результат зберігається в пам'яті на 10 хвилин. Сторінка запитує події на сьогодні й завтра при запуску і кожні 10 хвилин.

Обмеження: багатоденна подія показується лише в перший день; повтори типу «другий вівторок місяця» не підтримуються.

## Власні елементи керування

У сторінці немає елементів, які малює система. Кожен замінений так, щоб решта коду нічого не помітила:

| Системний елемент | Чим замінено | Де значення |
|---|---|---|
| `<select>` | `Dropdown(sel)`: кнопка зі списком поруч із прихованим `<select>` | У самому `<select>`; вибір викликає його подію `change`. Після зміни варіантів треба викликати `sel.refresh()` |
| `<input type="date">`, `type="time"` | Кнопка `.pick` і вікно `#dlgPick` | У прихованому `<input>` з тим самим `id`, у звичному вигляді `РРРР-ММ-ДД` / `ГГ:ХХ`. Після запису значення з коду треба викликати `refreshPicks()` |
| `<input type="number">` | Обгортка `.stepper` з кнопками `data-step` | У самому полі; кнопки викликають його подію `change` |
| Прапорець | Стилі: галочка в списках завдань, клас `switch` — перемикач, у `#hDays` — «пігулки» днів | У самому прапорці |
| `alert()`, `confirm()` | `tell(текст)` і `await ask(текст, кнопка)` — вікно `#dlgAsk` | `ask` повертає `true` лише за головну кнопку |
| Екран вибору програм Android | Вікно `#dlgApps`, список дає міст `AndroidBridge.listApps()` | Зберігає `AndroidBridge.setApps()` |
| Смуги прокрутки, виділення тексту | Стилі в кольорах теми | — |

Рамка вікна на ПК: `titleBarStyle: 'hidden'` з `titleBarOverlay` — Windows малює лише три кнопки, а за заголовок править шапка сторінки (`-webkit-app-region: drag`, клас `desktop` на `<html>`). Після зміни теми сторінка передає кольори оболонкам: `desktop.setChrome` перефарбовує кнопки вікна, `AndroidBridge.setChrome` — тло під системними панелями телефона та колір їхніх значків.

Системними лишаються лише речі, які сторінка намалювати не може: вибір файлу для відновлення копії, запити дозволів, сповіщення та меню значка в треї.

## Claude (MCP)

Інструменти для Claude описані один раз — у `server/mcp-tools.js` — і отримують «адаптер» до даних: `load()`, `put(col, record)`, `events(from, to)`.

- **Сервер** дає адаптер до своєї бази. Записи зберігаються за звичайним правилом синхронізації, тож пристрої отримують їх при наступному обміні.
- **Програма для ПК** дає адаптер до сторінки: `main.js` викликає `window.FocusStore` у вікні програми (`executeJavaScript`). `FocusStore.put` застосовує те саме правило «новіший `u` перемагає», зберігає, перемальовує й синхронізує — як ручну зміну. Тому програма має бути запущена; прихованої у треї достатньо.

Завдання звички на день, якого ще немає, інструменти обчислюють зі шаблону так само, як сторінка, і створюють, щойно треба записати відмітку чи нотатку.

Claude Code і Claude Desktop під'єднуються через місток `mcp-stdio.js` (stdio ↔ HTTP). Вхід `/mcp` у програмі для ПК відкритий лише для цього комп'ютера і захищений ключем, а також відхиляє запити з веб-сторінок (заголовок `Origin`) і з чужим `Host` — інакше будь-який сайт, відкритий у браузері, міг би змінити план.

## Мова

Код сторінки написаний українською. Для англійської нічого в коді малювання не змінюється: словник `EN` і список шаблонів `EN_RE` підміняють тексти вже на сторінці — спершу все, що є, а далі спостерігач за змінами перекладає кожен новий текст до того, як його побачить око. Тексти, які не потрапляють на сторінку (діалоги підтвердження, сповіщення, заголовок вікна), обгорнуті викликом `tr()`.

Щоб додати новий текст: напиши його українською в коді й додай пару в `EN` (або шаблон в `EN_RE`, якщо всередині є змінна частина).

## Оформлення

Три теми відрізняються лише значеннями змінних CSS. Сцена на екрані фокусу малюється на полотні й бере кольори з тих самих змінних. Музика синтезується засобами браузера: бас, «щітки», акорди, мелодія з випадковими паузами і тріск платівки; аудіофайлів у проєкті немає.

Логотип описаний у чотирьох місцях з однаковою геометрією: SVG у сторінці, `desktop/icon.js`, векторна іконка Android, PNG розширення.
