# Довідник з API

## Сервер

Базова адреса — `http://АДРЕСА:8090`. Усі адреси під `/api/` та `/mcp` вимагають заголовок:

```
Authorization: Bearer <FOCUS_TOKEN>
```

Без нього або з невірним ключем сервер відповідає `401`. Тіла запитів і відповідей — JSON.

### `GET /`

Віддає сам додаток (`index.html`). Ключ не потрібен.

### `POST /api/sync`

Обмін змінами.

Запит:

```json
{
  "since": 42,
  "changes": {
    "tasks":    [{ "id": "abc", "u": 1794335755197, "title": "…" }],
    "sessions": [],
    "stuck":    [],
    "kv":       [{ "id": "timer", "u": 1794335755197, "v": null }]
  }
}
```

- `since` — остання ревізія, яку пристрій уже має (0 — віддати все).
- У кожного запису обов'язкові `id` (рядок) і `u` (час зміни, мс). Запис приймається, лише якщо його `u` новіший за збережений.
- Окрім показаних, є колекція `habits` (звички). Якщо в запиті чи відповіді якоїсь колекції немає, це не помилка.
- `kv` — одиничні значення: `timer`, `settings`, `blocklist`.

Відповідь:

```json
{
  "rev": 57,
  "epoch": "252ea2fb356a2d26",
  "changes": { "tasks": [], "sessions": [], "stuck": [], "kv": [] }
}
```

- `rev` — поточна ревізія; її пристрій передає як `since` наступного разу.
- `epoch` — ідентифікатор бази. Якщо він змінився, базу було створено заново.
- У `changes` — усі записи з ревізією, більшою за `since`, зокрема щойно надіслані.

### `GET /api/state`

Поточний таймер — для служби блокування на телефоні.

```json
{ "timer": { "kind": "focus", "min": 25, "taskId": "abc", "title": "…", "startAt": 0, "endAt": 0 } }
```

Коли таймера немає — `{ "timer": null }`.

### `GET /api/calendar?from=РРРР-ММ-ДД&to=РРРР-ММ-ДД`

Події календаря за проміжок, включно з обома днями. Без параметрів — сьогодні.

```json
{
  "configured": true,
  "events": [
    { "date": "2026-11-10", "start": "08:30", "end": "10:05", "allDay": false, "title": "Лекція", "location": "ауд. 12" }
  ]
}
```

Для подій на весь день `start` і `end` дорівнюють `null`. Час — у часовому поясі сервера (`TZ`).

### `PUT /api/config`

Зберігає адресу календаря.

```json
{ "icalUrl": "https://calendar.google.com/calendar/ical/…/basic.ics" }
```

Адреса має починатися з `https://`; порожній рядок вимикає календар. Відповідь: `{ "configured": true }`. Збережена адреса ніколи не повертається.

### Коди помилок

| Код | Коли |
|---|---|
| `400` | Адреса календаря не починається з `https://` |
| `401` | Немає ключа або він невірний |
| `404` | Невідома адреса |
| `405` | `/mcp` викликано не методом POST |
| `500` | Внутрішня помилка; текст у полі `error` (наприклад, календар недоступний) |

## Інструменти для Claude (MCP)

Однаковий набір інструментів працює у двох місцях: у програмі для ПК (`POST http://127.0.0.1:47600/mcp`, дані — ті, що в програмі) і на сервері (`POST /mcp`, дані — база сервера). Код спільний — `server/mcp-tools.js`.

Протокол — JSON-RPC 2.0 без стану. Підтримуються `initialize` (повертає ще й `instructions` — правила «Фокуса» для Claude), `ping`, `tools/list`, `tools/call`.

| Інструмент | Параметри | Що робить |
|---|---|---|
| `get_schedule` | `from`, `to` (`РРРР-ММ-ДД`, до 31 дня; за замовчуванням сьогодні) | План по днях: завдання (сьогодні — і прострочені), звички зі станом, події календаря, хвилини фокусу, поточний таймер |
| `list_tasks` | `status` (`open` / `done` / `all`), `from`, `to`, `unplanned` | Завдання, без звичок |
| `add_task` | `title` (обов'язково), `first_step`, `why`, `plan_date`, `plan_time`, `deadline`, `note` | Створює завдання |
| `update_task` | `id` (обов'язково), ті самі поля, `done` | Змінює лише передані поля; порожній рядок очищає поле |
| `delete_task` | `id` | Видаляє завдання |
| `list_habits` | — | Звички з днями, часом, мінімумом, сигналом, нотаткою і станом за 14 днів |
| `add_habit` | `title` (обов'язково), `days` (`mon`…`sun`; за замовчуванням щодня), `time`, `minimal_version`, `cue`, `note` | Створює звичку |
| `update_habit` | `id` (обов'язково), ті самі поля | Змінює звичку; сьогоднішнє невиконане завдання звички змінюється разом із нею |
| `delete_habit` | `id` | Видаляє звичку; минулі відмітки лишаються в статистиці |
| `mark_habit` | `habit_id` (обов'язково), `date` (за замовчуванням сьогодні), `state` (`done` / `minimal` / `not_done`), `note` | Відмітка й нотатка за день; майбутні дні й дні, що не належать звичці, відхиляються |
| `get_stats` | `days` (1–60, за замовчуванням 7) | Хвилини фокусу по днях, виконані завдання, підсумок кожної звички, причини відкладання |

Стани звички за день: `done`, `minimal`, `missed`, `pending` (сьогодні, ще не відмічено), `upcoming` (майбутній день).

Помилки в даних (невірна дата, неіснуючий `id`, день не тієї звички) повертаються як результат з `isError: true` і зрозумілим текстом — Claude бачить, що виправити.

Завдання виглядає так:

```json
{ "id": "ce9418ad2e2d8", "title": "…", "first_step": "…", "why": "", "plan_date": "2026-11-17", "plan_time": "15:00", "deadline": "", "done": false, "done_at": "", "note": "" }
```

### Місток для Claude: `mcp-stdio.js`

Claude Code і Claude Desktop запускають `node mcp-stdio.js` і спілкуються з ним через stdin/stdout. Місток пересилає кожне повідомлення на `http://127.0.0.1:47600/mcp` з ключем із `%APPDATA%\Focus\mcp-token`, а якщо програма не запущена — запускає `Focus.exe --hidden` і чекає до 30 секунд.

Змінні `FOCUS_PORT` і `FOCUS_TOKEN_FILE` направляють місток на іншу копію — лише для перевірок.

## Програма для ПК

### `POST http://127.0.0.1:47600/mcp`

Інструменти для Claude (див. вище). Доступні лише з цього комп'ютера і лише з ключем:

- заголовок `Authorization: Bearer <ключ з %APPDATA%\Focus\mcp-token>`, інакше `401`;
- запит із заголовком `Origin` (тобто з веб-сторінки в браузері) отримує `403`;
- запит, де `Host` — не `127.0.0.1:47600` чи `localhost:47600`, отримує `403` (захист від підміни адреси).

### `GET http://127.0.0.1:47600/state`

Доступна лише з цього ж комп'ютера, без ключа. Її читає розширення.

```json
{ "active": true, "endAt": 1794338129565, "title": "…", "lang": "uk", "sites": ["youtube.com"] }
```

Поки фокус не триває, `active` дорівнює `false`, а `sites` порожній.

### Параметри запуску `Focus.exe`

| Параметр | Що робить |
|---|---|
| `--hidden` | Стартувати одразу в трей, не показуючи вікна (так запускає Windows при вході) |
| `--user-data-dir=<папка>` | Тримати дані в іншій папці — зручно для перевірок, щоб не чіпати справжні |

## Мости між сторінкою та оболонками

Сторінка завжди викликає їх через `?.`, бо в звичайному браузері їх немає.

### `window.desktop` (програма для ПК)

| Метод | Що робить |
|---|---|
| `setFocus(state)` | Передає стан: `active`, `endAt`, `title`, `sites`, `apps`, `lang` |
| `remind()` | Підняти вікно з трею без перехоплення клавіатури й підсвітити на панелі завдань |
| `show()` | Показати вікно й перевести на нього фокус |
| `setChrome(color, symbolColor)` | Кольори трьох кнопок вікна: тло і самі значки, у вигляді `#rrggbb` |
| `getMcpInfo()` | Шлях до містка `mcp-stdio.js` для блоку «Claude» в налаштуваннях |
| `getAutostart()` | Чи ввімкнено запуск із Windows; `null`, якщо програма запущена з коду |
| `setAutostart(on)` | Увімкнути чи вимкнути запуск із Windows |

### `window.AndroidBridge` (Android)

| Метод | Що робить |
|---|---|
| `setFocus(json)` | Той самий стан, але рядком JSON |
| `setServer(url, token)` | Адреса й ключ сервера — щоб служба могла спитати про сесію, запущену на ПК |
| `setReminders(json)` | Список майбутніх нагадувань: `[{ id, at, title, step }]`; замінює попередній |
| `listApps()` | Встановлені програми рядком JSON: `[{ p: пакет, n: назва, on: чи блокується }]`, за абеткою |
| `setApps(json)` | Замінити список блокування масивом назв пакетів |
| `setChrome(color, light)` | Колір тла під системними панелями і чи мають їхні значки бути темними (світла тема) |
| `openAccessibility()` | Відкрити спеціальні можливості Android |
| `blockingEnabled()` | Чи ввімкнена служба блокування |
| `blockedCount()` | Скільки програм вибрано |
